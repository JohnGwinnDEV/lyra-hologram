# Presentation events v1 — local iteration 1 subset

These dictionaries are in-process mock inputs, not a LYRA-Core integration
protocol. No network transport or serialization is implemented. The controller
must deliver events serially and avoid reentrant dispatch from state signals.

Every event requires integer `schema_version: 1` and string `type`.
Request/playback events also require a nonblank string `request_id`, unique
within a state-machine instance. Extra fields are ignored. Event IDs, utterance
records, clock cues, and audio assets are deferred until their first consumer.

| Event | Allowed source | Destination |
| --- | --- | --- |
| `presentation.ready` | OFFLINE | IDLE |
| `input.simulated` | IDLE | LISTENING |
| `input.cancelled` | LISTENING | IDLE |
| `request.started` | IDLE, LISTENING | THINKING |
| `request.completed` | THINKING | IDLE |
| `playback.started` | THINKING | SPEAKING |
| `playback.completed` | SPEAKING | IDLE |
| `request.cancelled` | Active request | IDLE after confirmed stop |
| `presentation.error` | Any initialized state | ERROR after confirmed stop |
| `presentation.reset` | ERROR | IDLE with `ready: true` and no unresolved request |
| `presentation.shutdown` | Any state | OFFLINE after confirmed stop |

LISTENING is simulated input only. THINKING is request pending, not cognition.
Playback start events must represent actual playback start. Text-only mock
responses use `request.completed`.

`handle(event)` returns `{ok: true}` on acceptance, or `{ok: false, code: ...}`
for invalid events, unsupported versions, unknown events, invalid transitions,
duplicate request IDs, unavailable readiness, or unsuccessful audio stopping.
Validation errors preserve state. Completed/cancelled request IDs remain retired;
their late callbacks and repeated cancellation return `{ok: true, ignored: true}`.
The in-memory retired-ID set grows with requests; session reset/recreation is the
current bound. Do not reuse an ID within an instance.

The injected speech backend exposes synchronous `stop() -> bool`. A true result
confirms stopped playback; this iteration uses a fake only. A false result enters
ERROR and retains the active request so cancellation/shutdown can retry. Reset
cannot bypass unresolved playback. Future asynchronous audio needs an explicit
stop acknowledgement contract before integration.

`state_changed(previous, current)` fires once per actual state transition.
Callers must finish component readiness checks before sending `ready: true`.

## Desktop mock timing

`MockEmbodimentController` drives the local lifecycle without network requests.
It advances using an injected frame delta and retires its scheduled phase on
cancel, error, and shutdown. The pending phase lasts 0.75 seconds; silent speech
simulation lasts 2.5 seconds. Its `playback.*` events are simulated, and its
speech backend only acknowledges stop. Do not interpret these events as evidence
of physical audio output. Real audio must replace these simulated callbacks.

`presentation_changed(state, dialogue)` supplies the desktop status and renderer.
The procedural avatar accepts presentation states and elapsed frame time; it
does not select responses or make decisions. All dialogue is fixed script text.
